## Reviewed and deliberately left open

- Recovery routes bind a challenge to a caller-chosen `node_key_version` (current or pending). While a rotation is pending an outsider on the recovering lane can pin the wrong key for a node. Belongs to RC09-RR03. The body-read timeout half is already covered: the global 10 s `request_timeout` closes stalled recovery bodies and frees the slot (regression test `p06_rc09_rr03_slow_recovery_bodies_release_their_slot_within_the_deadline`, passed on first run, so not red-first). **The pinning half is still open:** first open wins in `blindpass_authority.open_recovery_challenge`, so fixing it means an authority-schema change (supersede an unstaged challenge) and a layout bump; it needs a decision.
- `recovery_receipt_scope` fences the owner on any error, including a missing snapshot binding. Recovering lane only; attended state.
- Backup custody: the single recovery credential both signs and decrypts, and plaintext key material is staged under the output directory. Needs an ADR 0010 decision (split signing from recipient key, tmpfs staging).
- ~~PostgreSQL recovery transactions use READ COMMITTED~~ **Fixed 2026-10-05** (PostgreSQL restore now exists): `prepare`, `invalidate`, snapshot bind and application transactions run `SET TRANSACTION ISOLATION LEVEL REPEATABLE READ` first. Test `p06_ri07_postgres_recovery_transactions_use_repeatable_read` (trigger records `transaction_isolation` for controller_recoveries, grants and operations) was red, then green. Driver reruns: recovery_invalidation 7+7, restore_stage 23+23, recovery_receipts 6, restore_postgres 5 (in image). A concurrent-writer serialization-failure test was not written.
- `restore` reports failure when only the post-publish quiesce fails; `tool_with_deadline` blocks a worker (CLI only).
- Broker: the recovery commands are open to the control group (needed by the unprivileged relay); `recovery_generation` can ratchet the node pin epoch to the maximum for any holder of the issuer key; the state mutex is held across snapshot IO; the 30 s export window and stale temp-file sweep. Not changed.
- Release script can publish one archive before a later one fails.
