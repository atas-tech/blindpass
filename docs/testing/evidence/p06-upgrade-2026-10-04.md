## Built

- `blindpass-controller migrate [--pre-upgrade-backup-dir DIR --recovery-key-file KEY]` (also `blindpass migrate`): under the fenced authority record, an older supported SQLite schema (16 to current−1) is migrated only after an encrypted backup of it is published and independently re-verified (schema and tenant checked). Backups live in `DIR/pre-upgrade-<ms>-v<schema>/`; the three newest are kept, unrecognized names and links untouched. Current schema: verify only. Newer, older than 16, damaged, active-owner or PostgreSQL: refused unchanged with no backup. The backup runs outside the 30 s maintenance window with the guard held and rechecked before the migration.
- The snapshot opener accepts a supported older schema for read-only snapshots only (nothing else serves old state).
- Native: `blindpass-controller-upgrade.service` (hardened oneshot, recovery key via `LoadCredential`, authority drop-in) and `controller-install.py --upgrade` (newer version only, controller stopped, recovery-key custody checked, new tree beside the old, atomic selector switch, version record last; uninstall removes every recorded tree). Without `--upgrade` any different artifact is still refused.
- Compose: `deploy/controller/compose.upgrade-sqlite.yml` (`upgrade` profile).
- Runbook: `docs/deploy/upgrade.md`.
