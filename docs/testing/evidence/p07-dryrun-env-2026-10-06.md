## Findings made while building the environment

1. **`release.yml`'s image job would have failed its own verify step (fixed).** The documented command
   (`docker buildx build ... --output type=oci,dest=...`) produced in-toto statements whose `subject` list is empty, so
   `tests/deployment/controller-sbom.py` ("wrong attestation subject") and `scripts/release/extract-image-sbom.py`
   ("attestation subject is not the image it is bound to") both refused the archive. An older P06 archive passes because
   it was built with an image name (`pkg:docker/blindpass-p06-controller@pg-sbom?...` is its subject). The same build with
   `--tag ghcr.io/atas-tech/blindpass-controller:0.1.0` passes both. Fix: `--tag "$IMAGE_REPOSITORY:$VERSION"` added to
   the buildx invocation; a new test in `scripts/tests/release-workflow.test.mjs` ("the image build is named …") failed
   first (14 of 15) and passes now (15 of 15). Not proven on a hosted runner, which has not run.
2. **The `.oci.tar` release asset cannot be loaded with `docker load` on the default (overlay2) image store**
   (`invalid archive: does not contain a manifest.json`). An operator needs `skopeo copy oci-archive:… docker-daemon:…`,
   a registry pull after publication, or the containerd image store. The documents must say which; whether they do is
   part of what the dry run will show.
3. **Debian ships a system user named `operator`** (uid 37), so a cloud-init user of that name silently fails to be
   created ("Failed to create user operator") and the key is never installed. Environment detail only; the guest user is
   `bpadmin`.
4. The controller image's binaries are compiled in the image's own build stage; the archive binaries come from the
   `scripts/release/Dockerfile` export stage. They are built from the same tree but are not claimed to be bit-identical.

## What this environment does and does not model

- **Models:** a downloader with a signed asset set; a bare Debian 12 host with systemd and apt; a Docker host with the
  release image available under its published name; Chromium for the console; the documents limited to the quickstarts
  and what they link to.
- **Does not model:** a human (the operator is a model agent); the real release key (throwaway, fingerprint given
  out of band); real endpoints, DNS or TLS certificates (nothing is published; no public hostname exists); a GHCR pull
  (the image is pre-loaded); a hosted-runner build (all assets were built locally from an uncommitted tree); the
  aarch64 profile; the Arch desktop app (the archive and PKGBUILD are present but the dry run has no Arch host);
  a second node host (only the one guest exists, so a quickstart that needs another machine will stop there and say so);
  links from the quickstarts to files outside the copied set (they will not resolve here and are not findings unless the
  document says the target is needed).
- **Still not run:** P07-E01 itself, P07-E03 rollback, the endpoint probes of P07-E02, and any hosted workflow.
